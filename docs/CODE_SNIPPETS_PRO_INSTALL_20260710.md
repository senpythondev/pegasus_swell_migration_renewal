## 2. 読込順ゲート（コードで確定・実測は認証後）

Pro版 `class-evaluate-assets.php` を精読して確定：

1. **上書き可否（最重要）：✅ 上書きできる。**
   - Code SnippetsのCSSは **`wp_enqueue_scripts` 優先度 15** でenqueue（`enqueue_css`/`enqueue_css_flat_files`）。
   - 子テーマ `style.css` は functions.php で **優先度 11** でenqueue。
   - **15 > 11 のため、Code SnippetsのCSSが子テーマより後に読み込まれ、上書きが効く。** → 3層構造（③が②を上書き）の前提が成立。
2. **出力形式：✅ 外部ファイルモードあり（inline肥大回避可）。**
   - `Snippet_Files::is_active()` が真なら **CSSを物理フラットファイルに書き出し `wp_enqueue_style` でenqueue**（`class-snippet-files.php`）＝**外部ファイル・ブラウザキャッシュ可**。
   - 非フラット時は `?code-snippets-css` の仮想URLが**Expiresヘッダ付き**でCSSを配信（キャッシュ可）＋条件付きスニペットのみ `wp_add_inline_style`。
   - いずれも **リビジョン番号（`code_snippets_assets_rev`）でキャッシュバスティング**。→ 前回懸念の「inline肥大」は**外部ファイルモードで回避可能**。
3. **優先度制御：✅ あり。** スニペットは `priority` 列を持ち、出力順を制御可能（トークン→セクションの順序付けが可能）。
4. **`:root` 変数：✅ 使用可。** site-cssスニペットは通常のCSSとして連結出力されるため、`:root{ --pega-* }` を定義するスニペット（pega-tokens）を最優先で効かせられる（＝トークン中心設計の前提が成立）。

> **実測デモ（DBに site-css スニペットを挿入して確認）は未ライセンスのため出力されず。** 原因＝`class-evaluate-assets.php` の `init()` 冒頭 `if ( ! ...->was_licensed() ) return;`（**未ライセンスだとCSS/JS出力を一切行わない**）。→ **ライセンス認証後に実測で最終確認**する。
