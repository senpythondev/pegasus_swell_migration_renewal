## 2. 適用した変更

### 2-1. 管理系ポートの外部遮断（`docker-compose.yml`）

| サービス | 変更前 | 変更後 |
|---|---|---|
| phpmyadmin | `"8081:80"` | `"127.0.0.1:8081:80"` |

- nginx に `.htpasswd` を読み取り専用でマウント追加：`./.htpasswd:/etc/nginx/.htpasswd:ro`。

### 2-2. Basic認証（`nginx.conf`）

- `server` ブロック全体に適用：
  ```nginx
  auth_basic "Pegasus Staging (Kensho)";
  auth_basic_user_file /etc/nginx/.htpasswd;
  ```
- **`.htpasswd`** は `openssl passwd -apr1`（MD5）で生成。ユーザー名は `pegasus`（パスワードは別管理）。
- **wp-cron 免除**：WordPress自身のループバック要求（認証情報を持たない）が401で止まらないよう、`location = /wp-cron.php { auth_basic off; … }` を追加。
- **CF7フォーム送信への配慮**：ブラウザは一度Basic認証を通すと、同一オリジンの XHR/fetch（CF7の `wp-json` 送信・`admin-ajax`）にも認証情報を自動付与する。よって**管理画面ログイン・フォーム送信は認証下でも正常動作**（検証済み §4）。`wp-json`/`admin-ajax` をあえて除外していないため、未認証の直叩きは401で弾かれる（不正送信対策にもなる）。

### 2-3. 反映方法

- nginx構文チェック（`nginx -t`）= OK。
- `docker compose up -d nginx phpmyadmin mailpit` で**該当3サービスのみ再作成**。`db`・`wordpress` は `Running`（再作成されず・無停止）。

## 5. 大野様のアクセス方法（SSHトンネル）

phpMyAdmin・mailpit は外部公開しなくなったため、**SSHトンネル（ローカルフォワード）**でアクセスする。手元PCから：

```bash
# phpMyAdmin と mailpit を同時にトンネル（VPSへSSHできる前提）
ssh -L 8081:127.0.0.1:8081 -L 8025:127.0.0.1:8025  <user>@220.158.21.114

# 上記接続を張ったまま、手元ブラウザで：
#   phpMyAdmin → http://localhost:8081/
#   mailpit    → http://localhost:8025/
```

- 仕組み：手元の `localhost:8081/8025` への通信が、SSH経由でVPS内の `127.0.0.1:8081/8025`（＝各コンテナのループバック公開ポート）へ転送される。外部に晒さずに閲覧できる。
- SMTP（1025）はホスト公開していないが、WordPress→mailpit の送信はコンテナ間ネットワーク（`mailpit:1025`）で完結するため、トンネル不要（メール閲覧は8025のUIで行う）。
- サーバー上で直接作業する場合は、これまで通り `http://localhost:8081/`・`http://localhost:8025/`（ホストのループバック）で到達可能。
